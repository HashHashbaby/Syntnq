# SYNESTHESIA

> Hear the music. See its signature.

SYNESTHESIA turns a song into a visual signature: a **64 × 64 grid of glowing dots** where each
cell is a *kind of sound* the song contains, laid out by sonic similarity (a self-organizing map),
not by time. Companion maps (feature grids, structure, rhythm, dynamics) come from the same
analysis, and during playback the grid moves as a live liquid field that follows the audio.

Status: **M0 (scaffold)**. The analysis pipeline arrives in M1; see
[`docs/MILESTONES.md`](docs/MILESTONES.md).

## Setup

Requirements: [uv](https://docs.astral.sh/uv/) (it installs Python 3.11 for you), `ffmpeg` and
`libsndfile` for decoding compressed audio, and `make` (optional; every target is a plain `uv run`
command).

```bash
make setup      # uv sync + pre-commit hooks
make lint       # ruff check, ruff format --check, mypy --strict
make test       # pytest
```

Without `make`: `uv sync`, `uv run ruff check`, `uv run ruff format --check`, `uv run mypy`,
`uv run pytest`.

### Windows notes

- **`uv` not on PATH.** If you installed it with `pip install --user uv`, the `uv` script may not
  be on PATH. Run it as a module instead: `python -m uv sync` (or `py -3.12 -m uv sync`), and
  `python -m uv run pytest`, and so on. Installing uv from its official installer also fixes this.
- **`make`.** Windows has no `make` by default. With MinGW installed, use `mingw32-make` from
  `C:\MinGW\bin` (add that folder to PATH, or call it by full path): `mingw32-make setup lint test`.
  Every target is a plain `uv run ...` command, so you can also run those directly.
- **uv managed-Python link error.** On the first run, when uv downloads the pinned Python, it can
  end with `error: Missing expected target directory for Python minor version link ...`
  (seen with uv 0.13.0 on Windows 11). The interpreter is installed anyway. Either re-run
  `uv sync` (the second run succeeds), or point uv at the interpreter once:
  `uv sync --python <path to uv's python.exe>` (find it with `uv python find 3.11`).
  Verified by uninstalling the managed Python and syncing again: the first sync fails, the second
  works, and no flag is needed after that.
- The Python version is pinned in `.python-version` (3.11.17); CI uses the same file.

## Commands

| Command | What it does | Available |
| --- | --- | --- |
| `make setup` | install dependencies and git hooks | M0 |
| `make lint` | ruff + mypy | M0 |
| `make test` | pytest | M0 |
| `make test-determinism` | only the `determinism`-marked tests | M0 |
| `make analyze SONG=file.mp3` | analyze a song into `out/<song_id>/` | M1 |
| `make render SONG_ID=<id>` | render the signature PNG | M1 |
| `make preview SONG_ID=<id> SECONDS=20` | liquid-grid MP4 with audio | M3 |
| `make calibrate`, `make compare-sizes` | color calibration, grid-size check | M2 |
| `make api-dev`, `make web-dev`, `make web-test` | API and web app | M6, M7 |

`uv run syn config-hash` prints the SHA-256 of the resolved configuration.

## Where things live

- `config/default.yaml`: every tunable parameter (single source of truth).
- `docs/`: specs; read the relevant one before working on an area (see `CLAUDE.md`).
- `src/synesthesia/`: the Python package. `tests/`: unit, integration and golden tests;
  synthetic audio is generated by `tests/fixtures/make_signals.py`.

## Data and licensing

No audio is committed. Uploaded audio is deleted after analysis by default. Licenses and
attributions are recorded for every track used (see `docs/DATA_RESEARCH.md`).
